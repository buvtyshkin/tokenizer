# Fisher Cost для SillyTavern

Точные токены и стоимость каждого ответа — из поля `usage` в ответе API, а не из локального токенизатора. Тот же принцип, что в fisher-frontend: четыре числа (вход, выход, кэш-запись, кэш-чтение), цена фиксируется в момент генерации, панель расходов по периодам и по чатам.

## Как это работает

Сервер Таверны пробрасывает SSE-поток от Anthropic в браузер байт в байт, но фронтенд читает из него только текст. Расширение перехватывает `fetch` к `/api/backends/chat-completions/generate`, раздваивает поток: Таверна получает свой экземпляр нетронутым, расширение из второго достаёт `usage` (`message_start` → вход и кэш, `message_delta` → выход). Дальше цифры привязываются к сообщению по событию `MESSAGE_RECEIVED` и пишутся в `chat[id].extra.fisher_cost` — то есть в файл чата. Перезагрузка страницы, свайпы, переустановка расширения — ничего не теряется.

Запросы, за которыми не следует новое сообщение (саммари STMemoryBooks, Copilot, Story Toolkit, `/gen` и т.п.), попадают в журнал как «служебные» — отдельной колонкой. Так видно, сколько стоит обвязка, а не только игра.

## Установка

```bash
scp -r fisher-cost root@<vps>:~/SillyTavern/data/default-user/extensions/
```
Обнови страницу (Ctrl+F5). Панель — Extensions → Fisher Cost; отчёт также открывается из меню «волшебной палочки» рядом с полем ввода (пункт «Расходы»).

## Что показывает

- **Под каждым ответом** — полная подпись на широком экране, компактная на узком (переключается в настройках: авто / всегда компактная / всегда полная). Компактная: `in 19 · out 175 · CR 41,2k · CW 830 · 96% · $0.0045` — без модели, числа от 10 тысяч сокращены, при нехватке места переносится, а не обрезается. Полная: `claude-opus-5 · вход 19 · выход 175 · кэш ↓41 230 ↑830 · 96% · $0.0045`. Процент — кэш-хит (кэш-чтение от всего входа): зелёный ≥85, жёлтый ≥50, красный ниже. Наведи — подсказка с разбивкой кэш-записи по TTL (5 мин / 1 час), если API её прислал.
- **Отчёт:** сегодня, 24 часа, 7 дней, 30 дней, текущая вкладка; этот чат (сумма по самим сообщениям); разбивка по чатам за выбранный период со средней ценой ответа; по моделям.
- **CSV:** дневные агрегаты по чатам и моделям.

## Цены

`pricing.json` в папке расширения — доллары за миллион токенов по официальной таблице Anthropic (сверено 7 сентября 2026), ключ — префикс id модели (берётся самый длинный совпавший). Для каждой модели две цены кэш-записи: `cache_write_5m` (1.25× входа) и `cache_write_1h` (2× входа). Если API прислал разбивку `cache_creation` по TTL — берутся оба поля по факту; если нет — то, что выбрано в настройке «кэш-запись без разбивки считать как» (по умолчанию 1 час, под наш `extendedTTL: true`). Правки поверх файла можно вносить в панели (JSON), перечитать — кнопкой в отчёте. Стоимость уже посчитанных ответов при смене цен не меняется — это то же решение, что мы приняли для фронтенда.

Модель без цены: токены показываются, вместо цены — «цена?», в отчёте звёздочка.

## Провайдеры

| Источник в Таверне | usage в стриме | Кэш | Особенности |
|---|---|---|---|
| Claude (Anthropic) | да | чтение + запись 5м/1ч | разбивка записи по TTL из API |
| Google AI Studio / Vertex | да (`usageMetadata`) | чтение (неявный кэш) | thinking-токены считаются как выход; у Pro тариф ×2 при промпте >200k |
| Moonshot / Kimi (родной источник) | да (`choices[0].usage`) | чтение | запись в кэш бесплатна |
| DeepSeek | да | чтение | пиковые часы 01–04 и 06–10 UTC по будням — полная цена, иначе ×0.5 — считается автоматически |
| xAI / Grok | да | чтение | от 200k промпта весь запрос ×2 |
| Custom (OpenAI-совместимый) | только с `stream_options.include_usage` — расширение добавляет само | чтение (+запись у OpenAI 5.6+) | — |
| OpenAI (родной источник) | **нет** — Таверна не просит usage, а вписать нечем | — | подключай OpenAI через Custom с URL `https://api.openai.com/v1` |

В таблице цен 48 моделей: Claude, Gemini 2.5–3.8, GPT-5.4–6, Grok 4.1–4.6, Kimi K2.6–K3, DeepSeek V4. Сроки: Gemini 3.6/3.7/3.8 Flash — вводные цены до 31.12.2026 (с января удваиваются), GPT-5.6 Sol — промо до 21.11.2026. В тултипе под ответом видно, сработал ли тариф длинного контекста или непиковый.

## Кэш-рефрешер

Пинги [Cache-Refresh-SillyTavern](https://github.com/OneinfinityN7/Cache-Refresh-SillyTavern) идут как «тихая» генерация — без стриминга, с `max_tokens: 1`. Расширение узнаёт их по этой паре признаков (non-stream + `max_tokens` ≤ 8) и не ругается тостом, а пишет в журнал отдельной строкой «рефреш».

- **Custom / OpenAI-совместимые** (NanoGPT, Moonshot): сервер Таверны отдаёт non-stream JSON провайдера как есть, `usage` в нём есть — пинг считается точно.
- **Claude и Google напрямую**: сервер разворачивает non-stream ответ в `{choices}` и `usage` выбрасывает. Стоимость пинга **оценивается** по последнему ответу в этом чате: у Google весь промпт по цене чтения кэша (неявный кэш покрывает всё), у Claude — `кэш ↓ + кэш ↑` по цене чтения, `вход` по полной (хвост за точкой кэша), выход — `max_tokens` пинга. В отчёте такие суммы помечены «≈». Если Google промахнулся по кэшу, реальная цена пинга выше оценки в 10 раз — по подписи следующего ответа (0% хита) это будет видно.

Рефреш-пинги входят в общую сумму периода, но не в «служебные» и не в число ответов. В CSV — колонки `refresh` и `refresh_cost_usd`.

## Ограничения

- **Нужен стриминг.** Без него сервер Таверны разворачивает ответ Claude и Google и отдаёт клиенту только текст, `usage` теряется на сервере. Расширение предупредит тостом (кроме пингов рефрешера — см. выше). Для Custom-источника non-stream `usage` читается из JSON.
- **Anthropic напрямую** — работает из коробки. **Moonshot / Kimi K3** (api.moonshot.ai через источник Custom) и другие OpenAI-совместимые провайдеры присылают `usage` в стриме только при `stream_options.include_usage: true` — расширение само дописывает это в тело запроса для Custom-источника (галочка в настройках, по умолчанию включена). Кэш у Moonshot неявный и бесплатный на запись, поэтому в подписи будет только `CR` (cache-hit по $0.30). Если usage так и не пришёл, расширение скажет об этом тостом.
- Журнал живёт в `settings.json`: сырые записи — 48 часов, дневные агрегаты — 120 дней. Суммы «этот чат» от журнала не зависят.
- Перехват `fetch` — единственный способ добраться до потока. Если разбор упадёт, Таверна всё равно получит оригинальный ответ.

## Счётчик токенов: разбивка промпта и токены сообщения

Родной счётчик Таверны считает **все** модели Claude одним замороженным файлом
`src/tokenizers/claude.json`. С Opus 4.7 токенизатор сменился, и расхождение
доходит до трети. Prompt Itemization наследует ту же ошибку, поэтому здесь
токены считает сам Anthropic — через `/v1/messages/count_tokens`, тем же
токенизатором, каким считает модель.

### Что показывает

- **Строка над чатом** — сколько токенов в каждой части того, что уходит модели:
  `чат · лорбук · промпт · карточка · персона · всего`. Чат считается **без
  скрытых** сообщений (`/hide` помечает их `is_system`). Лорбук — только реально
  сработавшие записи, из события `WORLD_INFO_ACTIVATED`. На узком экране
  подписи сокращаются, числа от 10 тысяч тоже; строка переносится, а не
  обрезается.
- **Токены сообщения** — в той же строке под сообщением, где модель и цена, в
  конце: `… · $0.0045 · 1 284 тк`. Есть и под своими сообщениями, где данных
  `usage` нет, — тогда в строке только это число.

Обе части отключаются в настройках расширения по отдельности.

### Серверный плагин

Ключ Anthropic не должен попадать в браузер, поэтому запросы к `count_tokens`
делает серверный плагин: он берёт ключ из хранилища Таверны и ходит к API сам.

```bash
mkdir -p ~/SillyTavern/plugins/fisher-tokens
cp server-plugin/index.mjs ~/SillyTavern/plugins/fisher-tokens/
```

В `config.yaml` включите плагины и перезапустите Таверну:

```yaml
enableServerPlugins: true
```

Имя файла обязано быть `index.mjs`: в `plugins/package.json` объявлен
`"type": "commonjs"`, и `index.js` был бы прочитан как CommonJS, а плагин —
ES-модуль.

В логе при старте должно появиться:

```
[fisher-tokens] ready — POST /api/plugins/fisher-tokens/count
```

Без плагина расширение продолжает работать как раньше — строка над чатом просто
скажет, что счётчик недоступен.

### Сколько это стоит

`count_tokens` — отдельная точка API, токены генерации она не тратит, но у неё
свой лимит запросов. Поэтому:

- результат каждого блока кэшируется по хешу текста, повтор бесплатен;
- сообщение считается **один раз** и запоминается в файле чата
  (`extra.fisher_tokens`), пересчёт — только если текст изменили;
- старый чат заполняется постепенно, по шесть сообщений раз в секунду с
  небольшим, чтобы не упереться в лимит.

Каждый вызов оборачивает текст в сообщение, что само по себе стоит несколько
токенов. Плагин один раз замеряет эту надбавку для модели и вычитает её, так
что числа — вес самих секций, и сумма сходится.
